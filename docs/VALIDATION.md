# 공개 정리 시 검증 기록

검증일: 2026-10-15. 실제 WSL 작업본에서 소스를 추출한 뒤 공개용 복사본을 검사했습니다.

| 검사 | 방법 |
|---|---|
| Python 구문 | 제어 앱·재현 도구·LeNet 학습 스크립트를 `py_compile`로 검사 |
| 제어 시나리오 | 차선 유지, 중앙 객체 정지·감속, 측방 하단 객체 감속, 각도 입력·포화 |
| 통신 파싱 | 분할·연속 JSON, 문자열 내부 중괄호·escape, 빈 객체 결과 병합 |
| CAN 송신 간격 | fake IPC에서 같은 값의 중복 억제와 주기적 재전송 |
| C 소스 | framebuffer 도구 빌드, 로컬 ENLIGHT 실제 헤더로 NPU 소스 object 컴파일 |
| 셸 스크립트 | `sh -n` 구문 검사 |

결과: Python 테스트 9개 통과, Python·셸 구문 검사 통과, framebuffer 도구 및 NPU 소스 3개 컴파일 성공. `custom_postproc.c`에서는 실습 당시 남긴 미사용 변수·인자 경고 5개가 발생했습니다.

이 검사는 실제 모델 출력과 tensor layout의 일치, 보드 추론 속도·정확도, IPC/CAN 장치 출력, VCP 전체 BSP 빌드를 검증하지 않습니다.

## 남아 있는 제약

- softmax 후처리와 INT8 argmax 후처리는 서로 다른 실습 구현입니다. softmax 축과 no-lane 처리·row 방향도 따로 확인해야 합니다.
- NPU 출력 shape와 메모리 배치를 고정 가정합니다. 다른 모델 변환 설정에 자동 대응하지 않습니다.
- 조향 참고값은 가장 바깥 유효 차선들의 하단 좌표 중심을 사용합니다. 자차 좌우 차선을 추적해 선택하거나 조향 안정성을 보장하는 제어기가 아닙니다.
- Python 판단은 단순한 객체 영역·면적 기준입니다. 가장 큰 객체 하나를 선택하며, 모든 객체의 충돌 위험을 종합하지 않습니다.
- 인지 결과 timestamp와 통신 단절 시 정지 watchdog이 없습니다. 차선 송신이 생략되면 이전 차선값이 남을 수 있습니다.
- C 송신부는 고정 길이 JSON 버퍼를 사용합니다. 대량 탐지 결과와 송신 지연·오류 상황은 추가 검증이 필요합니다.
- framebuffer 뷰어는 32bpp 환경을 가정하며 보드의 pixel layout·offset 검증이 필요합니다.

학습·시스템 통합 과정을 설명하는 저장소이며, 차량용 제품 수준의 검증이나 안전성을 주장하지 않습니다.
